# Coding Conventions

## 1. File naming

| Kind          | Convention                                    | Example                          |
| ------------- | --------------------------------------------- | -------------------------------- |
| Component     | `PascalCase.tsx`, one main component per file | `TaskCard.tsx`                   |
| Page          | `PascalCase` + `Page` suffix                  | `TaskBoardPage.tsx`              |
| Hook          | `useCamelCase.ts`                             | `useTaskFilters.ts`              |
| Store         | `kebab-case.store.ts`                         | `auth.store.ts`                  |
| Zod schema    | `kebab-case.schema.ts`                        | `login.schema.ts`                |
| Test          | same name + `.test.ts(x)`, next to the file   | `TaskCard.test.tsx`              |
| Other modules | `kebab-case.ts`                               | `http-client.ts`, `nav-items.ts` |

Files in `components/ui` keep the names generated by shadcn.

## 2. Identifier naming

- Components, types, interfaces: `PascalCase`. Props interface: `XxxProps`.
- Variables, functions, hooks: `camelCase`; hooks start with `use`.
- Constants: `UPPER_SNAKE_CASE` (`MAX_UPLOAD_SIZE_BYTES`); constant objects too (`ROUTES`, `NAV_ITEMS`).
- Booleans: `is/has/can/should` prefix (`isOverdue`, `canApprove`).
- Event handler props: `onXxx`; handler implementations: `handleXxx`.

## 3. TypeScript

- `strict` and `noUncheckedIndexedAccess` are on. **`any` is forbidden** - use `unknown` and narrow.
- Avoid `as` casts; never use non-null `!` except where it is guaranteed (e.g. `#root`).
- `import type` for type-only imports (enforced by ESLint).
- `interface` for object shapes and props; `type` for unions, mapped and utility types. Do not use `React.FC`.
- API types come from `src/api/generated/models`; never redeclare them by hand.
- Named exports everywhere, **except page components**, which use `export default` for lazy loading.
- No hard-coded paths or business numbers: use `ROUTES` and `config/constants.ts`.

## 4. React

- Function components and hooks only.
- Keep components small (about 150 lines max); extract sub-components or custom hooks when they grow.
- Put logic (data fetching, derived data, permission checks) in hooks; components mostly render.
- Do not use `useEffect` to derive or sync state - compute during render or with `useMemo` when expensive. Never fetch data in `useEffect` (use TanStack Query).
- Stable keys (ids) for lists; never array indexes for reorderable lists.
- Lift state only as high as needed; avoid prop drilling deeper than 2 levels (use composition or a store).

## 5. Clean code

- One responsibility per function and component; early returns instead of nested conditionals.
- No duplicated logic: extract to a hook, `utils/` or a shared component.
- No dead code, unused exports, `console.log`, or commented-out code.
- Handle every async state: loading, error and empty.

## 6. Formatting and linting

- Prettier decides layout: no semicolons, single quotes, 100 columns, trailing commas, Tailwind classes sorted automatically.
- Imports are sorted by `simple-import-sort` (run `npm run lint:fix`).
- `eslint-disable` needs a reason on the same line and is a last resort.
