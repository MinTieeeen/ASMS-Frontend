# State Management and API Access

## 1. Where state lives

| Kind of state                                 | Location                                                                              |
| --------------------------------------------- | ------------------------------------------------------------------------------------- |
| Server data                                   | TanStack Query (Orval hooks). **Never** copy it into Zustand or `useState`            |
| Session (access token, current user)          | `stores/auth.store.ts` - token kept **in memory only**, never in localStorage (NFR06) |
| Global UI state (sidebar, preferences)        | Zustand store in `stores/`                                                            |
| Feature UI state shared by several components | Zustand store in `features/<name>/stores/`                                            |
| Shareable view state (filters, tab, page)     | URL search params                                                                     |
| Form state                                    | React Hook Form + Zod                                                                 |
| Local UI state                                | `useState` / `useReducer`                                                             |

Zustand: select the smallest slice (`useAuthStore(selectIsAdmin)`), export selectors next to the store, keep actions inside the store.

## 2. Calling the API

- **Never** call `axios` or `fetch` directly from components. Use the hooks generated by Orval in `src/api/generated`; every request goes through `api/http-client.ts` (adds the token, refreshes on 401).
- When the backend changes, run `npm run api:gen`, fix type errors, and commit the regenerated files. Never edit `src/api/generated` by hand.
- Wrap generated hooks in `features/<name>/api/` only when extra behaviour is needed (cache invalidation, optimistic update, data shaping).
- After a mutation, `invalidateQueries` for exactly the affected query keys.
- Drag and drop on the task board uses optimistic updates with rollback on error.

## 3. Errors and async states

- Every API error is an `ApiError` (`status`, `code`, `fieldErrors`) - see `types/api.ts`.
- Validation errors: map `fieldErrors` into the form with `form.setError`.
- Business errors: show a translated toast (`sonner`) chosen by `code` (e.g. `GROUP_FULL`); fall back to a generic message.
- Every data view handles loading (`Skeleton` / `LoadingScreen`), error (with retry) and empty (`EmptyState`) states.

## 4. Permissions in the UI

- Hide or disable actions according to the group permission matrix (requirement section 3.2) using a feature hook such as `useGroupPermissions(groupId)`.
- This is UX only; the backend always enforces permissions, so handle `403` gracefully.
