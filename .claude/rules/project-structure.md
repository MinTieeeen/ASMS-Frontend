# Project Structure

## 1. Folder layout

```
src/
├── app/                  # Application assembly
│   ├── App.tsx
│   ├── providers/        # AppProviders: theme, QueryClient, tooltip, toaster
│   └── router/           # route tree (lazy pages), guards (RequireAuth / RequireAdmin / GuestOnly), 404 page
├── api/
│   ├── http-client.ts    # the only Axios instance: token header, refresh on 401, Orval mutator
│   └── generated/        # GENERATED by Orval - never edit by hand, committed to git
├── components/
│   ├── ui/               # shadcn primitives (CLI generated), no business logic
│   ├── common/           # app-wide building blocks: PageHeader, EmptyState, LoadingScreen, ThemeToggle
│   ├── form/             # form fields bound to React Hook Form: FormTextField, ...
│   └── layout/           # AppLayout, AuthLayout, AppHeader, AppSidebar, nav-items
├── config/               # env.ts, routes.ts (ROUTES), constants.ts (BRxx constants)
├── features/             # business modules (section 2)
├── hooks/                # generic hooks: useDebounce, useDisclosure, useMediaQuery
├── lib/                  # third-party setup: utils (cn), i18n, query-client
├── locales/{vi,en}/      # translation namespaces: common.json, auth.json, ...
├── stores/               # global Zustand stores: auth.store (in-memory token), ui.store
├── styles/               # globals.css (entry) + theme.css (design tokens)
├── test/                 # setup.ts, render.tsx (renderWithProviders)
├── types/                # shared types: api.ts (ProblemDetail, ApiError, PageResponse), auth.ts
└── utils/                # pure functions: date.ts (BR13), format.ts
```

`lib/` wraps or configures third-party libraries. `utils/` holds our own pure, side-effect-free helpers.

## 2. Feature modules

| Feature         | Requirement | Scope                                                             |
| --------------- | ----------- | ----------------------------------------------------------------- |
| `auth`          | M01         | Login, register, password reset, email verification               |
| `profile`       | M01         | Profile and personal settings                                     |
| `dashboard`     | M07         | Personal dashboard across all groups (UC11)                       |
| `groups`        | M02, M03    | Groups, subject/semester info, members, invites, join requests    |
| `phases`        | M04         | Phases, closing a phase, retrospectives                           |
| `tasks`         | M05         | Board / list / calendar views, task detail, comments, attachments |
| `milestones`    | M06         | Milestones, deliverables, results                                 |
| `reviews`       | M08         | Peer review rounds and aggregated results                         |
| `notifications` | M10         | In-app notification center                                        |
| `admin`         | M12         | User, catalog, group and report management                        |

Inside a feature, create sub-folders only when needed:

```
features/tasks/
├── api/            # wrappers around Orval hooks (invalidation, optimistic updates), query keys
├── components/     # components used only by this feature: TaskCard, TaskBoard, TaskDetailSheet
├── hooks/          # useTaskFilters, useTaskPermissions
├── pages/          # route-level components, default export (lazy loaded): TaskBoardPage.tsx
├── schemas/        # Zod form schemas: task.schema.ts
├── stores/         # feature-local Zustand stores (e.g. filters)
├── types.ts        # UI-only types (API types come from api/generated)
└── index.ts        # public API of the feature
```

## 3. Dependency rules (one direction)

```
app  ->  features  ->  components / hooks / stores / lib / utils / config / types / api
```

- `components/`, `hooks/`, `lib/`, `utils/`, `stores/` **never** import from `features/`.
- A feature never imports another feature's internals; it may import only what that feature exports from its `index.ts`. If two features need the same thing, move it to a shared folder.
- A component used by one feature stays in that feature. When a second feature needs it, promote it to `components/common`.
- `components/ui` contains only shadcn primitives; app-specific wrappers go to `components/common` or `components/form`.
- Always import through the `@/` alias; relative imports are allowed only within the same folder (`./AppHeader`). ESLint blocks `../../`.
