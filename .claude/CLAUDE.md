# ASMS Frontend

Single-page application of **ASMS (Assignment Management System)**, a web platform that lets students manage their course group projects in one place: groups, members, phases, tasks (board / list / calendar), submission milestones, peer reviews, dashboards and system administration.

- **Specification:** [`../../docs/Assignment_Management_System_Requirement.md`](../../docs/Assignment_Management_System_Requirement.md). Read the relevant use cases, business rules and the permission matrix (section 3.2) **before** building a screen.
- **Traceability codes** used in comments, test names and commits: `Fxx.yy` feature, `UCxx` use case, `BRxx` business rule, `NFRxx` non-functional requirement.
- **Backend:** Spring Boot API in `../asms-backend`. It owns the API contract (OpenAPI); the frontend generates its client from it and never re-declares API types by hand.

## Tech stack

| Area             | Technology                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------- |
| Build / language | Vite 8, TypeScript 6 (strict), React 19                                                   |
| Routing          | React Router 7 (data router, lazy routes)                                                 |
| Styling          | Tailwind CSS 4 (CSS-first config, no `tailwind.config`)                                   |
| Components       | shadcn/ui (Radix base, Nova preset), `lucide-react` icons, `sonner` toasts, `next-themes` |
| Server state     | TanStack Query 5 + hooks generated by **Orval 8** from OpenAPI, Axios                     |
| Client state     | Zustand 5                                                                                 |
| Forms            | React Hook Form + Zod 4                                                                   |
| i18n             | i18next + react-i18next (Vietnamese by default)                                           |
| Dates            | date-fns 4 + date-fns-tz                                                                  |
| Testing          | Vitest 5, Testing Library, jsdom, MSW                                                     |
| Quality          | ESLint 9 (flat config) + Prettier (+ Tailwind class sorting)                              |

Libraries chosen by the requirement but **installed only when needed**: `@dnd-kit/*` (task board), `@tanstack/react-table` (lists, admin), `@fullcalendar/*` (calendar), `recharts` (charts), `@tiptap/*` (rich text, @mentions), `@stomp/stompjs` (realtime, phase 3).

## Commands

```bash
npm run dev            # http://localhost:5173 - /api is proxied to http://localhost:8080
npm run build          # tsc -b + vite build
npm run typecheck
npm run lint           # lint:fix to auto-fix
npm run format         # Prettier write; format:check for CI
npm test               # Vitest once; test:watch while coding
npm run api:gen        # Regenerate the API client from http://localhost:8080/v3/api-docs (backend must run)
npx shadcn@latest add <component>   # Add a shadcn component to src/components/ui
```

Environment: copy `.env.example` to `.env.local`. Only `VITE_*` variables reach the bundle; read them through `@/config/env`.

## Project structure at a glance

Full details in [rules/project-structure.md](rules/project-structure.md).

```
src/
├── app/          # App assembly: providers, router, route guards
├── api/          # http-client.ts + generated/ (Orval output, never edited by hand)
├── components/   # ui/ (shadcn) · common/ · form/ · layout/
├── config/       # env, routes, business constants
├── features/     # one folder per business module (auth, dashboard, groups, tasks, ...)
├── hooks/        # generic reusable hooks
├── lib/          # third-party setup: cn(), i18n, query client
├── locales/      # vi/ and en/ translation namespaces
├── stores/       # global Zustand stores
├── styles/       # globals.css + theme.css (design tokens)
├── test/         # test setup and render helpers
├── types/        # shared types
└── utils/        # pure helper functions
```

## Golden rules

1. Read the specification first; if it is ambiguous, **ask** - never invent business behaviour.
2. The UI hides or disables actions by permission for UX only; the backend is the real guard.
3. Code, identifiers and comments are written in **English**; all user-facing text goes through i18n (Vietnamese default).
4. Every hand-written source file carries the standard header (see code-comments.md).
5. Nothing is "done" until `lint`, `typecheck`, `test` and `build` all pass.
